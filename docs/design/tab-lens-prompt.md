# 为什么你的 tab 不能拖动 + 没有折射

先看差距在哪。图一那个「镜头」不是玻璃背景本身，是**四层东西叠出来的**：

1. **几何**：每个 tab 在 bar 本地坐标里的 Rect（`onGloballyPositioned` 注册）。
2. **录制**：把整条 bar 的内容录进 `GraphicsLayer`，绘制时把镜头区域裁掉，镜头自己画一份放大的。
3. **手势**：按下涨起 → 过 touchSlop 进入拖动 → 边缘橡皮筋 → 速度驱动压扁 → 松手回弹并选中。
4. **折射**：`RuntimeShader` 按圆角矩形 SDF 的法线偏移采样背后内容。

你的图二只有第 1 层的一半（静态选中胶囊）+ 模糊底色，缺 2、3、4，所以：

- 胶囊只能按等分位置平移，不能跟手；
- 下方图标不会被放大（没有 layer 录制）；
- 没有拖动状态机（press / drag / settle），长按自然没反应；
- 没有 shader，就只有「模糊 + 染色」，不可能有边缘折射。

另外纠正一点：NeriPlayer 是**按下即涨起**，不是等长按。要长按也行，但会慢半拍。

## 给 AI 的提示词

```text
你是 Android Compose 工程师。任务：给底部 tab 加「按下拖动镜头」和「边缘折射」。
现状：底部在 <文件>，选中态是静态胶囊，背景只有模糊+染色，没有拖动。
目标：按下即涨起（不需要长按等待），拖动时镜头跟手并放大下方 tab，
松手落到最近的 tab 并切换。

第一阶段：几何与手势（先不做视觉）
- 每个 tab 用 onGloballyPositioned 注册坐标到 BarState（bar 本地坐标，忽略上层变换）。
- 用 Animatable 保存镜头中心，跟随选中 tab。
- 自定义 pointerInput（awaitEachGesture）：
  down 时涨起；移动超过 touchSlop 进入拖动并 consume 事件；
  横向位置限制在首尾 tab 中心之间，越界做 6% 橡皮筋；
  每个 move 用 VelocityTracker 记速度；松手按最近 tab 中心 bouncy 回弹并切换选中。
- 拖动经过不同 tab 时给一次 haptic。
- 普通轻点仍要能触发 tab 自己的 click。

第二阶段：镜头外观（仍不折射）
- 把 bar 内容录进 GraphicsLayer；绘制时把镜头区域 clip 掉（ClipOp.Difference），避免重影。
- 镜头是独立 overlay：位置 = bar 坐标 + 胶囊 rect，允许溢出 bar（bar 本身不要 clip）。
- 胶囊 rect：静止 = tab 宽内缩 4dp、高 = bar 高 - 8dp；按下时 scale 1 → 1.34。
- 镜头内放大 bar 内容：以胶囊中心为轴 scale 1 → 1.2，用 SrcIn 着色成 primary。
- 加 14dp 阴影（随按下进度）、8dp 模糊内阴影（15% 黑）、顶部 1px 高光边。
- 速度驱动 squash：沿行进方向拉伸、垂直方向压扁（上限 14% / 6%）。

第三阶段：折射（API 33+，可选）
- 用 RuntimeShader 采样镜头下方内容：圆角矩形 SDF 求法线，
  sample = p - normal * refraction * (1 - depth)²；
  refraction 4dp、edgeBand 12dp，强度随按下进度 0 → 1。
- 只在镜头边缘带折射，中间保持原样。
- 不支持时（API < 33 或用户关闭液态玻璃）退回第二阶段，不报错。

验收
- 按住 tab bar 拖动：镜头跟手、放大下方图标、经过即切；松手回弹到最近 tab。
- 轻点仍能切 tab，不会误触发拖动。
- 关掉液态玻璃：仍有涨起+放大+阴影，只是没有折射。
- API < 33 不崩；连续快速拖动 20 次不掉帧。

边界：不改 tab 的业务跳转；不新增依赖；每阶段可编译并录屏。
```

## 三个最容易踩的坑

- **bar 被 clip 成胶囊**：镜头永远出不来。要 `clip = false`，把裁剪留给内容层。
- **只用 `animateDpAsState` 移动胶囊**：那是「选中动画」，不是「拖动」。必须有 pointerInput 状态机。
- **用 `Modifier.blur` 当折射**：那是整层模糊。折射必须有 shader 对背后内容做偏移采样，
  这也是为什么图二看着「平」——没有法线、没有边缘带、没有高光。

## 五件套对照

| 元素 | NeriPlayer | 你的图二 |
|---|---|---|
| 跟随手指 | 有（Animatable + rubber band） | 无 |
| 放大下方内容 | 1.2 倍 layer 复制 | 无 |
| 阴影 / 内阴影 / 高光 | 14dp / 8dp / 1px | 无 |
| 边缘折射 | 4dp / 12dp 带 | 无 |
| 松手回弹 | bouncy + 选中 | 只有选中渐变 |

# 补：镜头涨开超出胶囊的边界

## 先对齐事实

NeriPlayer 的镜头**是允许小幅溢出的**，不是完全收在框里：

- 纵向：静止高度 = bar 高 − 8dp = 56dp；按下 ×1.34 ≈ 75dp；
  溢出 = (75 − 64) / 2 ≈ **5.5dp**（上下各一点）。
- 横向：首尾 tab 按住时，宽度 ×1.34 会越过胶囊左右端约 **9dp**（按 3 tab、360dp 宽估）。
- 它之所以看着「没出框」，是因为镜头**居中对称**、阴影只有 14dp，且 bar 左右各留了 16dp 屏幕边距。

所以如果你的溢出明显更多，问题通常不是「该不该溢出」，而是**缩放基准错了**。

## 你大概率错在这四处

1. 缩放的是**外层容器**（含 padding / 阴影 / 屏幕边距），而不是镜头 rect 本身。
2. 镜头高度基准用了 `barHeight`，而不是 `barHeight − 8dp`，倍数再一乘就翻倍。
3. 用 `Modifier.shadow(elevation = 14.dp)`，阴影画在 clip 之外，看着像“漏出框”。
4. 镜头是 bar 的兄弟节点，父容器没 clip，横向也没 clamp 到 bar 内边距。

## 提示词（直接粘）

```text
你是 Android Compose 工程师。修复：底部 tab 的选中镜头按下涨开时，超出底部胶囊的外框。
现状：镜头放大后上下/左右都能看到溢出胶囊。
目标：任何时刻镜头边界都不超出胶囊外框；放大、放大内容、高光、阴影都保留。

实现要求
1. 先量后画：镜头 rect 由「tab rect + bar 的内边距」推导，最终必须 clamp 到 bar 的 bounds：
   左右各留 4dp、上下各留 4dp。clamp 后尺寸不够就压缩 scale，不许出框。
2. 缩放基准用镜头 rect 自身（宽、高），不要缩放包含 padding 的外层容器。
3. 镜头 layer 加 clip（形状 = 胶囊圆角）；阴影与高光改成「内阴影 + 内侧 1px 亮边」，
   不要用 Modifier.shadow 的大 elevation 往外投。
4. 想保留「抬升感」：用 1–2dp 位移 + 内阴影 + 顶部高光，不要靠继续放大。
5. 横向中心仍限制在首尾 tab 中心之间（现有 rubber band 保留），但扣掉 4dp 内边距。
6. 放大内容（1.2 倍）与边缘折射保留，采样范围限制在镜头内。
7. 加一个开关 containLens：true = 完全收在胶囊内（默认）；false = 允许小幅溢出（≈5dp）。

验收
- 在第一个和最后一个 tab 按住拖动，镜头四边都不超出胶囊外框。
- 快速拖动、松手回弹过程中，不出现任何一帧溢出。
- 放大内容仍可见、折射仍在（API ≥ 33）。
- 关掉液态玻璃后行为一致，只是不折射。
- 提供一张开启 debug 边框的截图，证明镜头 bounds ⊆ bar bounds。

边界：不改 tab 业务跳转；不新增依赖；改完给前后对比截图。
```

## 验收时怎么一眼看出有没有超

让 AI 在 debug 构建里给两个 bounds 画 1px 边框：bar 用红、镜头用绿。
绿框任何一边压过红线就是溢出，尤其在首尾 tab 按住的时候最容易露馅。
