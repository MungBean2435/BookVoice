# 三件事的提示词：液态玻璃 / 首启引导 / 子页返回不跳顶

不建议一次全发。这三件事风险差很多：

| 顺序 | 功能 | 风险 | 为什么排这个位置 |
|---|---|---|---|
| 1 | 子页返回不跳顶 + 返回策略 | 低 | 会动导航结构，先改完再叠视觉 |
| 2 | 首启引导 | 低 | 纯 UI + 几个布尔值，不碰播放 |
| 3 | 底部液态玻璃 | 高 | 涉及 RenderEffect / AGSL，最后做 |

另外有一个独立 bug（设置左上角返回卡死），单独一段，先修它再做视觉。

## 1. 状态保持 + 返回策略

```text
你是 Android Compose 工程师。任务：让页面状态在「子页返回」和「切 tab」后保留，
并统一设置页的返回行为。
工程：<工程路径>；导航：<NavHost/自研 tab 容器>；列表页：<书架/书签/设置>。

要修的两个现象
1. 从设置子页返回设置首页，列表不能跳回顶部，大标题的折叠状态也要保留。
2. 打开设置子页后切到别的 tab，再点回设置，要回到刚才那个子页（不是首页）。

返回策略（优先级从上到下，箭头 / 系统返回 / 手势共用同一个函数）
- 在设置子页：返回设置主页，不退出设置。
- 在设置主页：切回「主页/书架」tab，不退出 App。
- 已经在主页 tab：走系统默认（退出或进后台）。
- 转场进行中再按返回：只处理一次，不重复 pop。
- 禁止箭头写一套、BackHandler 再写一套。

状态保存
- 把每个页面的 LazyListState 提升到共享宿主（页面之外的 composable 或 ViewModel），
  用 rememberSaveable(saver = LazyListState.Saver) 保存；不要写在页面内部。
- 当前子页标识、TopAppBarState 同样提升并 rememberSaveable。
- 页面内部用互斥分支渲染：page == null 渲染首页，否则渲染子页；不要销毁宿主里的 state。
- tab 容器用 rememberSaveableStateHolder()，每个 tab 场景包
  SaveableStateProvider(route)，切走时自动保存、切回时恢复。
- 切 tab 的 navigate 加 popUpTo(startDestination){ saveState = true }、
  launchSingleTop = true、restoreState = true。
- 从设置进「下载管理」这类跨 scene 的页面，额外记录离开时的 index/offset，回来再恢复。

验收
- 子页返回后，列表 index/offset 与折叠进度与离开时一致。
- 子页按系统返回 → 回到设置主页；设置主页按返回 → 回到主页 tab。
- 连按 5 次返回，不崩、不卡死。
- 切 tab 再回来，仍停在子页。
- 旋转屏幕、进程被杀后重建，仍能恢复（至少 index/offset）。
- 返回手势拖动过程中，能看到下面的列表，不是白屏。

边界：不改业务逻辑；不新增依赖；每步可编译。
```

## 2. 首启引导（欢迎 + 分步设置）

```text
你是 Android Compose 工程师。任务：给听书 App 加首次进入的引导，第一次打开走引导，
之后直接进主界面。工程：<路径>；设置存储：<DataStore/SharedPreferences>。

启动判定
- 定义 StartupStage：Loading / Disclaimer / Onboarding / Main。
- 用两个持久化布尔值：disclaimerAccepted、onboardingCompleted。
  任一还没读到 → 停在 Loading，不要先闪主界面。
- 顺序：免责（如需）→ 引导 → 主界面。

步骤（5 步，每步只做一个决定）
1. 语言（最先，后面文案立刻本地化）
2. 书架来源 / 导入本地目录
3. 播放偏好（跳过静音、倍速、睡眠定时习惯）
4. 外观（深浅色、主题色、是否开启液态玻璃）
5. 说明页（3–5 张卡讲手势与功能）+「开始使用」

外壳
- maxWidth >= 600dp 双栏：左侧 32% 放标题和按钮，右侧内容卡；手机单栏。
- 头部：胶囊 badge、headlineSmall 粗体标题、bodyLarge 副标题、6dp 圆角进度条 + "3/5"。
- 按钮：返回（weight 1）+ 下一步（weight 1.4）；最后一步文案「开始使用」。
- 步骤切换：进入 360ms、退出 300ms，淡入 280 / 淡出 220；返回时按进度反演，不重置。

数据
- 每步的改动即时落库；最后一步只写 onboardingCompleted = true。
- 写入失败就停在当前步并提示重试，不要假装成功。
- 没有「跳过全部」；权限申请放到引导最后或引导结束之后。

验收
- 清数据后首启进入引导；完成后不再出现。
- 返回键逐步回退，动画反演。
- 旋转屏幕不丢当前步。
- 引导中修改的主题/语言，进主界面后立即生效。

边界：不改播放逻辑；不新增依赖；每步可编译。
```

## 3. 底部液态玻璃（分三档，别一步到位）

```text
你是 Android Compose 工程师。任务：把底部导航做成浮层胶囊，并加「液态玻璃」开关。
工程：<路径>；minSdk <..>；Compose/M3 <版本>；底部导航在 <文件>。

第一步：结构 + 视觉（不碰模糊）
- 三个 tab：书架 / 书签 / 设置；图标 + 10.5sp 标签；选中 primary，未选中 onSurface 72%。
- 胶囊：高 64dp、左右 16dp、底部 16dp + navigationBars inset、50% 圆角；
  阴影 18dp；0.5dp 描边（暗色 10% 白 / 亮色 70% 白）。
- 选中态：tab 背后一枚内缩 4dp 的小胶囊，200–360ms 平移；点按 haptic，无 ripple。
- 底色 surfaceContainerLow；有背景图时 alpha 0.62。
- 三个 tab 各自保存滚动位置，切换不重建。

第二步：玻璃三档
档 1（默认/不支持）：纯色 + 描边。
档 2（API 31+）：底部栏背后内容做模糊——整页快照挂 graphicsLayer.renderEffect，
  或用现成 backdrop-blur 方案；半径 28dp，tint 0.75。
档 3（API 33+）：在模糊层上加边缘折射：
  refraction 0.42、edgeBand 14dp、rim 1.6dp、rimHighlight 0.16；
  只让边缘窄带参与（(1-depth)² 权重），中间保持毛玻璃；
  开启后 tint 降到 0.48/0.56、edge 0.07。

第三步：开关与降级
- 设置 → 外观 加「液态玻璃」，默认关，持久化。
- 可用条件：SDK >= 33、非省电、非低内存；不满足时置灰并写明原因。
- 渲染失败或掉帧时自动回落档 2，不崩。
- RenderEffect 要缓存，滚动时不允许每帧重建。

验收
- 关开关 = 档 2；不支持 = 开关灰 + 原因。
- 滚动列表时底部跟着内容虚化，不是只糊壁纸。
- 手势条不压 tab，可点区域 ≥ 48dp。
- 连续切 20 次 tab 不掉帧、不涨内存。

边界：不新增依赖（要加先说明）；参考项目 GPL-3.0，只按行为与数值重写，不粘源码。
```

## 4. 修复「设置左上角返回卡死」

```text
你是 Android Compose 工程师。任务：修复设置页点左上角返回会卡死的问题。
现象：进入设置或设置子页后，点左上角返回，界面卡住/无响应（可能伴随转场不动）。
工程：<路径>；设置页：<文件>；导航：<...>。

先定位，再改。不要直接猜着改。
1. 抓证据
   - 复现时执行 adb shell kill -3 <pid>，拿主线程堆栈；或抓 ANR trace。
   - 看是主线程阻塞（IO/锁/同步等待）、无限重组，还是转场协程死等。
   - logcat 过滤 Choreographer 跳帧与 Navigation 的 pop/navigate 事件。
2. 逐个排除这些常见根因
   - 箭头 onBack 与系统 BackHandler 同时触发，pop 两次；
   - AnimatedContent 转场没结束就 pop，状态卡在中间；
   - 返回时在主线程写 DataStore/文件；
   - 返回后旧 scene 仍被持有，反复重组；
   - disabled 的按钮仍消费点击，或点击防抖缺失；
   - rememberSaveable 的 key 冲突导致反复恢复。
3. 修复要求
   - 返回逻辑收敛成一个函数：箭头、系统返回、手势都调它；
   - 加防重入标记：转场中或已发起返回时忽略第二次；
   - 写库移到 IO，失败回滚到原状态；
   - 不允许用 delay / Thread.sleep 掩盖问题。
4. 回归
   - 子页连点返回 10 次不卡；返回后立刻再进子页正常；
   - 旋转、低端机各复测一次；
   - 留下复现步骤与修复说明。

边界：只动返回链路与相关转场，不重构设置页整体；不新增依赖。
```

## 5. 如果一定要一次发

把上面四段拼起来，前面加一句：

> 先修第 4 段（卡死），再做第 1 段（状态与返回），然后第 2 段（引导），
> 最后第 3 段（玻璃）。每阶段结束先停下等我验收，不要跨阶段提前写 shader。

否则 AI 很容易先写 shader，再回头发现导航结构要改，白干。

## 6. 验收时你亲自看这 8 件事

1. 子页返回，列表停在原位（不是顶部）。
2. 子页按系统返回 → 设置主页；设置主页按返回 → 主页 tab。
3. 连按返回不卡死，箭头与系统返回行为一致。
4. 切 tab 回来，还在子页。
5. 清数据首启，引导能走完并只出现一次。
6. 引导里改的语言/主题，进主界面生效。
7. 关玻璃开关，底部仍然好看。
8. 开玻璃开关，滚动时底部跟着内容虚化。
