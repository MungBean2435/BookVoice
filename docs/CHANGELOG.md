# 版本历史

> 版本号规则：修 bug 升 patch，加功能升 minor，重构升 major。

## 3.4.x

**3.4.0** — 诊断面板、分卷目录与更完整的任务反馈
- 事件改为结构化记录（等级/标签），上限从 18 条提高到 300 条，可按「播放 / 合成 / 网络 / 问题」筛选，Warn/Error 分级着色。
- 顶部增加设备/版本/供应商/模型/音色/语速/播放状态/网络/缓存概览，指标增加上次合成耗时、流式重试、首包超时、断流、强制收尾、已开始块数。
- 新增「复制摘要」「导出诊断」「记录标记」「清空」：复制/导出只含版本、设备、配置名与事件，不含 API Key、服务地址、书名和正文。
- 导出走 SAF 文本文件，文件名带时间；清空只清诊断，不影响播放、缓存、书签和进度。
- 目录页改成书页头：封面、书名、作者、章节数；按卷折叠，当前卷自动展开，当前章高亮。
- EPUB 读取 EPUB3 nav / EPUB2 NCX 的层级目录，TXT 识别「第 X 卷 / 部 / 篇 / 集」；数据库升到 v4，新增 `volume` 列。旧书需要重新导入才有卷信息。
- 导入改成可取消、可逐本重试的任务卡，书架和引导页共用；失败列表最多显示 3 条，成功后自动收起。
- 播放错误不再只弹一次 Toast：正文上方保留常驻提示条，可重试或关闭；缓存本章可中途停止，完成时提示成功 / 失败段数。
- 书签删除后可在 Snackbar 里撤销；撤销会按原 id 和原创建时间重新插入。
- 修复目录页因折叠标题栏的 nestedScroll 截走滑动、目录打不开新版整页、打开书籍总从第一章开始、暂停后阅读位置不落库等问题。

## 3.3.x

**3.3.5** — 修掉重复的「播放器 ENDED」
- 上一块被看门狗强制收尾时只恢复了等待，没有移除 Player.Listener；下一块播完时旧监听器也收到 ENDED，于是日志出现两条。
- 强制收尾前先移除监听器，并记录当前活动监听器；ENDED/错误路径同样清理。
- 收尾余量 0.4s → 0.5s，避免最后一点尾音被切掉。

**3.3.4** — 修掉「隔一块才有预取」
- 3.3.3 只在本块走流式时预取下一块；一旦下一块命中缓存、改走文件播放，它就不会再预取，于是出现「缓存块 → 流式块（等首包）→ 缓存块」交替，2→3 块之间仍有约 1 秒空档。
- 现在文件播放路径也会预取下一块；正常序列里除第一块外都应命中缓存。

**3.3.3** — 缩短块间空档
- 当前块开始后，后台用流式接口预合成下一块并写入缓存（只对 MiMo 这类支持流式的供应商）；下一块直接读缓存文件播放，不再在块边界等 0.6–0.9 秒首包。
- 预合成使用 `streamPcm` 而不是 `ensureFile`：取消时会在 200ms 内断开连接，不会抱着 `synthMutex` 拖住下一块。
- 播放收尾余量从 2 秒降到 0.4 秒；预取的下一块在真正播放前若仍未完成，会先取消它再自己流式合成。

**3.3.2** — 收尾兜底不再被「位置一直在变」绕过
- 3.3.1 的绝对超时写在“位置未变化”分支后面，播放器若一直报告位置在走就永远到不了；现在提到最前面，按实际播放时长判断。
- 只累计非暂停的播放时间，暂停久了不会被误收尾。
- 看门狗取消不再记成异常事件。

**3.3.1** — 修正误判断流，并给播放收尾加绝对兜底
- 合成已经正常结束的块，不再在 12 秒后被判「中途断流」（3.3.0 日志里 25 秒合成完成、37 秒却报断流）。
- 看门狗增加停滞详情事件（位置/状态/播放标志/合成与缓冲状态），异常也会记录。
- 即使播放位置一直不动、状态判断全没命中，超过音频时长（按倍速折算）3 秒也强制收尾继续下一块。

**3.3.0** — 诊断页「最近播放事件」
- 在诊断页直接显示最近 18 条播放事件（每块开始、流式首包、合成完成/失败、12 秒断流、播放器 ENDED、播放错误、强制收尾、协程超时）。
- 播放停滞兜底放宽为「合成结束或缓冲区已收尾」，不再只看合成协程是否结束。
- 用于定位「读完一段就一直不读」：截图诊断页即可看到卡在哪一步，不需要导出包。

**3.2.4** — 播放器不进入 ENDED 时强制收尾
- 现象：诊断页「流式首包 746ms、回退 0、缓存未命中 1」，说明第一块已经开始播，但队列再没走到第二块。
- 原因：流式 WAV 声明未知长度，部分设备上 ExoPlayer 播完最后一段后没有触发 `STATE_ENDED`，`playMediaSourceAndWait` 永远不返回。
- 修复：合成协程结束后，若播放位置连续 3 秒不前进且仍处于 READY/BUFFERING/IDLE，就强制 `exo.stop()` 并结束本块，继续下一块；暂停时不触发。

**3.2.3** — 修复「读完一段就一直不读」
- 根因：流式协程取消后仍阻塞在 `readLine` 上，`invokeOnCompletion` 等协程结束才触发，形成死循环；播放器这边又无限 `job.join()` 等它退出，于是这一块播完播放队列永远停住。
- MiMo `streamPcm` 增加独立轮询：检测到协程取消后 200ms 内 `disconnect()`，让阻塞读立刻返回。
- 播放器等待合成协程退出最多 3 秒，超时记日志继续，不再无限等；合成锁随后释放，下一块能正常开始。
- 看门狗断流（12 秒无新 PCM）后也会走这条路径，不再卡在「已播完但没有下一段」。

**3.2.2** — 首包超时不再直接退回整块
- 流式 10 秒没收到首包时，不再改走整块合成（同一网络下整块只会更慢），改为立即重试流式，最多 2 次、间隔 1.5 秒；离线时先等网络恢复。
- 重试完仍一个 PCM 字节都没收到，直接提示「TTS 服务没有返回音频」，不再让用户白等 90 秒整块请求。
- 只有已经播出一部分、重试仍失败时，才回退整块重播以保证文本完整。

**3.2.1** — 断网时不再跳段
- 流式中途 12 秒没有新数据时先判断网络：离线则停在当前块、显示「网络中断」，等恢复后整块重播本块；只有网络正常、单块卡住时才记「待补」并跳过。修的是「跳过的下一块同样没数据」。
- 首包超时/流式失败时若网络不可用，也先等网络恢复再回退整块，不把整段直接判死。
- 清单新增 `ACCESS_NETWORK_STATE` 权限（只读网络状态，不涉及位置）。

**3.2.0** — MiMo 每块流式 + 播放调度修复；点读移到顶栏
- 流式不再只用于首块：MiMo 供应商下每一块都边收边播，块间不再出现「整块合成 20 秒」的空档。
- 播放调度修复：流式供应商关闭自动预取（预取会抢合成锁）；`ensureFile` 改成「每次拿锁只发一次请求，退避 `delay` 放到锁外」，预取最多等 30 秒就放弃该轮。这修的是「读几句后一直不读」——预取协程曾抱着 `synthMutex` 重试最长 10 分钟，播放队列只能干等。
- 流式看门狗：首包 10 秒未到就结束流式、回退整块合成重播；播到一半 12 秒没有新 PCM 就结束本块、记「待补」后继续，避免播放器卡在未知长度的 WAV 上。
- 诊断页新增「流式首包」「流式回退」两行；流式块写缓存后下次直接命中。
- 点读从 Aa 弹层移到顶栏：书签右侧新增独立图标（Material `touch_app` 路径），开启时主色高亮、关闭时 55% 灰；Aa 里只剩字号和说明，不再显示右上角圆点。
- 新增 `StreamingAudioTest`：WAV 头字段、真实长度、48 KB/s 时长换算、PcmStreamBuffer 读取 / EOF / 取消。

## 3.1.x

**3.1.0** — MiMo 首块流式合成：首声从 8 秒级降到 1 秒级
- 首块不再等整段 wav 合成完（150 字约 8.3 s），改用 MiMo 的 SSE 流式接口（`stream:true` + `pcm16`）：收到第一段 PCM（约 0.8–1.1 s）就交给 ExoPlayer 边收边播。
- 新增 `playback/StreamingAudio.kt`：`PcmStreamBuffer`（合成器写、播放器阻塞读）、`PcmStreamDataSource`（media3 DataSource，长度未知、读到 EOF 结束）、`PcmWav`（44 字节 PCM 头，流式写未知 data size，落盘缓存写真实大小）。
- `TtsProvider` 新增 `supportsStreaming` / `streamPcm`；`MimoProvider` 实现 SSE 流式，取消时断开连接；播放器启动时不再让预取先抢合成锁（否则首块要等第二块合成完）。
- ExoPlayer 起播门槛从默认 2.5 s 降到 500 ms；流式块进度用真实 PCM 字节数换算（`data size` 未知时不能用 `exo.duration`）。
- 流式失败自动回退整块合成并重播，Auth / Quota / TooLong 直接上抛；流式成功后仍把完整 wav 写入音频缓存，下次直接命中。
- 修复 3.0.0 里「40.5 s 首声」的根因场景：MiMo 非流式在 30 s `readTimeout` 上超时 + 2 s 退避 + 重试；流式首块不再整段等待。
